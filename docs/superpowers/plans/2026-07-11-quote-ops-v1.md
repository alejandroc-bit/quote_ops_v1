**Goal:** Rebuild the agentic freight-quoting system as `quote_ops_v1`: multichannel intake (email/WhatsApp), AI classification + extraction, deterministic quote engine, AI historical interpretation + bounded recommendation, human approval per policy, same-channel response with PDF, TMS writeback, local playground, cloud portal (Vercel + Supabase RLS), per-client bash installer, GitHub-release updates, and a weekly sentinel report per client.

**Architecture:** TypeScript npm-workspaces monorepo. The agent team is a real LangGraph.js `StateGraph` with a Postgres checkpointer for human-in-the-loop interrupts. All "already solved" pieces are copied from `/Users/alejandro/quote-system-v2-product` unchanged where possible: `packages/{contracts,connectors,quote-core,criteria,knowledge,audit,shared}`, `deploy/appliance`, intake (mailbox/xlsx), approvals API, control-plane installer generation. New code lives in `apps/agent` (LangGraph team), `apps/api` (appliance API + playground backend), `apps/playground` (step-by-step UI), `apps/portal` + `apps/control-plane-api` (cloud), `packages/quote-core` extensions (pricing-model plugins), sentinel, and updater.

**Tech Stack:** Node 22, TypeScript ESM, zod, vitest, `@langchain/langgraph` + `@langchain/langgraph-checkpoint-postgres`, `@langchain/openai` (OpenRouter-compatible = client-agnostic LLM), pdfkit, Vite + React (playground/portal UI), Express (APIs), Supabase (control plane, RLS), Docker Compose appliance (postgres+redis+caddy), GHCR images via GitHub Actions on tag `v*`.

## Global Constraints

- Package scope stays `@quoteops/*` (copied packages keep imports untouched). Repo/product name: `quote_ops_v1`.
- The LLM NEVER computes or alters a rate. `quote-core` is 100% deterministic; the recommender only annotates within criteria bounds (v2 invariant `recommended_rate_mxn === base_rate_mxn` is kept for the base; adjustments are separate fields gated by criteria).
- Client-owned data stays local (appliance Postgres / client cloud SQL). Cloud gets only: profile, credential metadata, usage counts, sentinel reports, releases. No route/quote detail in Supabase.
- Cache-aside everywhere: read local cache tables → miss → TMS adapter → write cache. Comparables key = route + unit_type + commodity.
- BYO LLM key: `agent-config.yaml` `provider` + `api_key_env` (reuse `AgentRuntimeConfig`). OpenRouter is the default provider (one API, any model).
- Docker images amd64-only (QEMU arm64 is flaky — v2 lesson).
- Fictitious client NMX only in tests/fixtures; product stays generic.
- Hostinger pilot MUST NOT touch the existing v2 install on srv1807611 (ports 8080/8443, /opt/quoteops, COMPOSE_PROJECT_NAME). New install uses `/opt/quoteops-v1`, distinct project name and ports.

### Task 2: Pricing-model plugins in quote-core

**Interfaces (produced):**
```ts
export type PricingModelId = 'margen_fijo' | 'rentabilidad' | 'completo';
export interface PricingInputs { km: number; tolls_mxn: number; fuel_price_mxn_l: number;
  kpl_yield: number; maintenance_mxn_km: number; operator_cost_mxn: number;
  insurance_pct: number; risk_pct: number; params: Record<string, number>; }
export interface PricingBreakdown { cost_mxn: number; rate_mxn: number;
  lines: Array<{ concept: string; amount_mxn: number }>; model: PricingModelId; }
export function computeQuote(model: PricingModelId, i: PricingInputs): PricingBreakdown;
```
- `margen_fijo`: `rate = cost * (1 + params.margin_pct)`.
- `rentabilidad` (RB): `rate = cost / (1 - params.target_rb)` — RB = (rate−cost)/rate.
- `completo`: rentabilidad + fixed overhead `params.overhead_mxn` + empty-return factor `params.empty_return_pct` applied to fuel+tolls.
Cost base (all models): `fuel = km/kpl_yield*fuel_price + tolls + km*maintenance + operator + insurance_pct+risk_pct over subtotal`.
**Tests:** vitest with exact numeric fixtures per model; model unknown → throws.

### Task 3: LangGraph state + graph skeleton (`apps/agent`)

**Interfaces (produced):**
```ts
// state.ts — Annotation.Root
run_id: string; channel: 'email'|'whatsapp'; message: NormalizedMessage;
intake_kind: 'single'|'multi_text'|'bulk_file'|null;
rfqs: Rfq[]; lanes: ResolvedLane[]; inoperable: {lane, reason}[];
quotes: (PricingBreakdown & {lane_id})[]; historical: HistoricalContext[];
recommendation: {lane_id, verdict:'auto'|'needs_review'|'unknown_route', reason, suggested_rate_mxn?}[];
approval: {action:'approve'|'adjust'|'reject', rate_mxn?}|null;
response_sent: boolean; steps: StepEvent[] (reducer: concat);
```
Nodes wired with `addConditionalEdges`: `classify → (bulk? validateOperability : extract) → resolve → quote → historical → recommend → policyGate → [interrupt] → respond → writeback`. Every node pushes a `StepEvent {node, started_at, finished_at, summary, data_redacted}` (playground feed) and an audit event. Checkpointer: `PostgresSaver.fromConnString(DATABASE_URL)`; `policyGate` uses `interrupt()` when verdict ≠ auto; approvals API resumes with `Command({resume})`.
**Tests:** graph run with stub LLM + FileImport TMS fixture: auto path completes; needs_review path interrupts and resumes.

### Task 6: Historical interpretation + bounded recommendation + policy gate
