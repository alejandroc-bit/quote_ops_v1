Guía de uso: del comando de instalación a la cotización aprobada

Esta guía documenta el proceso real ejecutado en el piloto: instalación por terminal, onboarding guiado con copiloto de IA, el playground local de operación, el flujo de cotización con aprobación humana y escritura al TMS, y el portal cloud. Cada captura y transcripción proviene de la corrida real.

348 tests verdes appliance v0.1.0 healthy cotización aprobada + writeback LangGraph agent team quote-core determinista

1 · Instalación con un comando

El proveedor (tú) genera un install pack por cliente en el plano de control. El cliente recibe un comando único y lo corre en su servidor:

QUOTEOPS_REGISTRATION_TOKEN="<token>" bash -c 'curl -fsSL https://quote-ops-portal.vercel.app/api/install/$QUOTEOPS_REGISTRATION_TOKEN | bash'

El instalador crea /opt/quoteops-v1 (config, secretos con permisos 600, manifiesto, plantillas del TMS), valida el compose y levanta 6 contenedores: postgres, redis, agente, api, web y caddy.

Resultado en el piloto

Env file: /opt/quoteops-v1/.env
Secrets env file: /opt/quoteops-v1/secrets/client.env
Manifest: /opt/quoteops-v1/manifests/client-manifest.yaml
TMS adapter config: /opt/quoteops-v1/connectors/tms-adapter.yaml

$ curl http://127.0.0.1:8090/health
{"ok":true,"product_version":"v0.1.0","workflow_runs":0,"heartbeats":0}

Nota del piloto: las imágenes GHCR son privadas por decisión de negocio, así que se precargaron con docker load y el instalador corrió con el flag nuevo --no-pull. En producción el cliente hace docker login ghcr.io con su sesión y el comando único funciona directo.

4 · Flujo de cotización: de la solicitud al TMS

Con la licencia activa, el appliance procesa solicitudes. En el piloto se inyectó una solicitud real por API (en operación llegará por correo/WhatsApp y el equipo de agentes LangGraph la clasifica y extrae con IA):

POST /api/playground/rfqs
{"origin_city":"Monterrey","origin_state":"Nuevo Leon","destination_city":"Guadalajara",
 "destination_state":"Jalisco","vehicle_profile_id":"T3S3_53_DRYVAN","weight_kg":18000,
 "commodity":"abarrotes","requester_email":"ops@loadlink.mx"}

→ {"run_id":"RUN-PILOTO-MRI9PWVS","rfq_id":"RFQ-2026-449912","status":"RECEIVED"}

El motor determinista calculó la tarifa y, al no haber histórico suficiente, la política la mandó a revisión humana (exactamente el comportamiento diseñado):

GET /api/rfqs
{"run_id":"RUN-PILOTO-MRI9PWVS","status":"REVIEW_REQUIRED","approval_required":true,
 "route_source":"sakbe","base_rate_mxn":1600,"recommended_rate_mxn":1600}

El aprobador decide (desde la página de Aprobaciones o por API) y el resultado se escribe al TMS:

POST /api/approvals/RUN-PILOTO-MRI9PWVS/decision {"action":"approve"}
→ {"approval_decision":{"action":"approve"},"writeback_result":{"quote_id":"quote-v2-RFQ-2026-449912-L01","status":"queued"}}

# connectors/tms/quote-writebacks.jsonl (el archivo que consume el TMS)
{"quote_id":"quote-v2-RFQ-2026-449912-L01","rate_mxn":1600,"currency":"MXN",
 "metadata":{"quote_core_version":"quote-core-2.0.0","pricing_model":"formula","route_source":"sakbe"}}

El equipo LangGraph completo (clasificación IA → extracción → resolución → cotización → histórico → recomendación acotada → gate de política → respuesta con PDF por el mismo canal → writeback) quedó verificado con una corrida interna de 24 pasos que terminó status=done con PDF generado. Se activa en producción al conectar el buzón del cliente.
